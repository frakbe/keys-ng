# Keys NG M1.18.1 — TUI editor regression fixes

Version: `0.1.18.dev1`

This maintenance release fixes two regressions found during real TUI review and adds an explicit password visibility control to both interactive front ends.

## Fixed

- **TUI modal inputs no longer alter the vault search.** `Input.Changed` events emitted by fields inside modal screens were bubbling to `KeysApp.on_input_changed()`. The handler treated every input event as if it came from the main search box, rebuilt the tree using the editor field value as a search query, and reset the current selection. This caused the vault to appear empty after cancelling an edit and also removed the object that the save callback relied on.
- **TUI edits are persisted reliably.** The entry UUID is captured before the editor modal is opened. On save, the callback reloads that entry by UUID, applies the shared `EntryDraft`, and persists it through `Vault.save_entry()`. The callback no longer depends on mutable UI-selection state.
- **Password reveal control in TUI.** The entry editor now provides a `Show` / `Hide` button that toggles Textual's password masking without changing the stored value.
- **Password reveal control in GUI.** The Qt entry dialog now provides the same `Show` / `Hide` behavior using `QLineEdit` echo modes.
- Italian gettext entries for the new controls were added and the `.mo` catalog rebuilt when `msgfmt` is available.

## Regression coverage

Added tests verify that:

- an edited entry can be saved and reloaded by a UUID captured before the modal is opened;
- only the main `#search` input drives TUI filtering;
- TUI save no longer depends on `current_entry` remaining selected;
- both GUI and TUI expose password visibility controls.

Final automated suite: **123 passed**.

`tools/security_static_check.py` also passes, and `python -m compileall` completes successfully.
