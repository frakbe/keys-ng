# Keys NG Vault Format 1.0

Status: **frozen for the M1.17 review cycle**. The serialized model schema value is `1`. Any incompatible future change must use a new schema value and an explicit migration path.

## Filesystem layout

```text
vault/
├── vault.json
├── catalog.gpg
├── folders.gpg
├── records/
│   └── <entry-uuid>.gpg
└── inbox/
    └── <deposit-uuid>.gpg
```

On POSIX, M1.17 creates the vault root, `records/` and `inbox/` as `0700`. Ciphertext/config atomic files use `0600` creation modes. UUID filenames do not contain titles or usernames.

## `vault.json`

Cleartext JSON policy, schema `1`:

- `recipients`: OpenPGP recipient fingerprints used for encryption.
- `signer`: signing fingerprint or `null`.
- `trusted_signers`: fingerprints accepted on decrypt when signatures are required.
- `require_signature`: whether unsigned/invalid/untrusted vault objects are rejected.
- `catalog_privacy`: `minimal`, `standard`, or `full`.
- `schema`: configuration schema (`1`).

This file must never contain passwords, TOTP seeds or decrypted entry contents.

## Record plaintext before OpenPGP encryption

Canonical UTF-8 JSON produced with sorted keys and compact separators. Fields:

- `schema`: `1`.
- `id`: UUID string; must equal the record filename UUID when opened through the vault.
- `title`: non-empty display title.
- `kind`: free descriptive type currently used by the UI/importers.
- `usernames`: list of strings.
- `password`: string or `null`; may contain a whole-field UUID reference.
- `totp`: list of TOTP objects (`secret`, `issuer`, `account_name`, `algorithm`, `digits`, `period`).
- `actions`: list of validated actions (`url`, `ssh`, `rdp`, `command`).
- `tags`: list of strings.
- `notes`: string.
- `custom_fields`: string-to-string map.
- `folder_id`: UUID or `null`.
- `revision`: positive integer.
- `created_at`, `updated_at`: UTC ISO-like timestamps generated by Keys NG.

Each record is encrypted independently to the configured recipients and normally signed by the configured signer.

## Folder store plaintext

`folders.gpg` encrypts JSON with `schema: 1` and a `folders` list. Every folder has UUID `id`, non-empty separator-free `name`, optional parent UUID, and timestamps. Parent references must exist and cycles are rejected.

## Catalog plaintext

`catalog.gpg` encrypts a rebuildable JSON snapshot containing `schema: 1`, `items`, and a snapshot of `folders`.

Each item stores UUID, title, kind, privacy-dependent usernames/tags/URL hosts, capabilities, entry revision, ciphertext SHA-256 and optional folder UUID. Passwords and TOTP seeds are never catalog fields.

M1.17 uses `ciphertext_sha256` plus `revision` as a binding between a record and the signed catalog. This detects isolated record replacement. It is not a global anti-rollback counter.

## References

Supported whole-field forms are:

```text
{REF:U@I:<UUID>}
{REF:P@I:<UUID>}
```

`U` resolves to the first username, `P` to the password. Resolution is same-vault, recursive, cycle-checked and bounded to 32 nested references.

## Inbox

Inbox deposits use the same encrypted Entry payload but are not catalog members. Public-key-only contributors may create unsigned deposits. Normal import rejects unsigned deposits unless the operator explicitly approves `accept_unsigned`; accepted entries are then validated and re-encrypted/re-signed under the vault's normal policy.

## Compatibility rule

Readers must reject unsupported schema numbers rather than guessing. Additive changes that cannot be represented safely by old readers require a schema bump. The M1.17 release does not claim compatibility with future schema values.
